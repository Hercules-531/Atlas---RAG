# Atlas-RAG implementation plan

Repository: https://github.com/Hercules-531/Atlas---RAG

Status: implemented locally; measured validation and live evaluation artifacts are in reports/. See README.md for setup and limitations.

## Product and constraints

Build a useful local-first RAG application for arbitrary user documents. Positioning: **minimum necessary, with proof**. Never promise guaranteed privacy. Optimize for usefulness (40%), efficiency (30%), reliability and safety (20%), and demo clarity (10%). Keep the application name in one configuration constant.

- All original files, extracted text, embeddings, vector indexes, history, consent records, token maps, and audit logs persist locally.
- Mode A uses local embeddings and loopback llama.cpp with the existing Unsloth Gemma 4 E4B model. Report application-observed external requests, not machine-wide network certification.
- Mode B sends only approved minimized prompts through Prune to vaulted Gemini. Prune and the provider see transmitted content.
- Use Gemini `gemini-3.5-flash-lite` on free quota only. Authorized paid spend is US$0. Never upgrade billing or switch to a paid provider/model automatically. Pause and resume evaluations on quota exhaustion.
- No deployable on-device Prune gateway has been established. Use the user's authorized direct-local-model exception in Mode A, disclose it in the README and UI, and do not invent local Prune receipts. All cloud generations go through Prune.
- Secrets come from backend environment variables. Commit only placeholder `.env.example`; ignore real environment files and runtime data. Never place keys in browser bundles or request audit headers.

## Architecture and storage

Use Python 3.12, FastAPI, SentenceTransformers, embedded persistent Chroma, SQLite, NumPy, React, TypeScript, and Vite.

```text
Browser -> FastAPI -> local parsers -> SQLite text/provenance
                              |
                    local EmbeddingGemma 2
                              |
                    persistent local Chroma
```

### Chroma and embeddings

- Use `PersistentClient` with an explicit local `data/chroma/` directory. No Chroma Cloud, hosted storage, or network-exposed Chroma server.
- Explicitly disable Chroma's default embedding function. Supply document vectors and query vectors directly, generated by the same local EmbeddingGemma 2 revision.
- Use local text-only EmbeddingGemma 2. On this machine, reuse the cached Unsloth GGUF through llama.cpp after conversion to F32, with CPU/F32 arithmetic. Conversion does not recover source-weight precision. Retain SentenceTransformers as an alternative, with unused vision/audio encoders disabled and BF16/FP32 inference; never FP16 runtime arithmetic.
- Follow the official question-answering query prefix and titled-document formatting. Validate every vector: 768 finite values, nonzero norm, normalized output.
- Download model assets during setup; use local files at runtime with no remote embedding fallback. Keep a small replaceable embedder interface.
- Store vectors, opaque IDs, and minimal retrieval metadata in Chroma; keep raw chunk text in SQLite. Use cosine similarity and document filters.
- Fingerprint model revision and preprocessing in collection identity. Refuse incompatible indexes and require reindexing.
- Disable telemetry and verify offline indexing/querying with external networking blocked.
- SQLite is the authoritative document registry. Pending and deleted documents cannot provide evidence, including after an interrupted Chroma operation.
- Delete-file removes original data, text, vectors, and dependent stored content. Delete-all removes application data and recreates an empty index; shared installed model weights remain. Do not claim forensic secure erasure.

## Increased ingestion defaults

| Limit | Previous plan | Revised default |
| --- | --- | --- |
| Uploaded file size | 25 MiB | **100 MiB per file** |
| PDF page count | 200 | **1,000 pages per file** |
| CSV/XLSX row count | 50,000 | **250,000 data rows per file**, across sheets |
| Extracted text | 5 MiB | **50 MiB UTF-8 text per file** |

These are independent limits: stop when any applicable limit is exceeded. Store them centrally in `config/app.toml`, with backend environment overrides `ATLAS_MAX_UPLOAD_MIB`, `ATLAS_MAX_PDF_PAGES`, `ATLAS_MAX_TABLE_ROWS`, and `ATLAS_MAX_EXTRACTED_TEXT_MIB`. Validate positive values at startup and expose effective limits through the public configuration API. Define MiB as 1,048,576 bytes.

- Support PDF, DOCX, TXT, MD, CSV, XLSX, and JSON using local parsers. Preserve source/page/paragraph/sheet/row/field offsets.
- Stream uploads to disk with a running byte counter. Never trust Content-Length as the sole size check or buffer the entire upload in memory. Clean partial uploads on failure/cancellation.
- Parse incrementally where supported: PDF page iteration, CSV row iteration, XLSX read-only iteration, and streaming JSON parsing. Embed in bounded batches with a single active ingestion worker.
- Enforce the extracted-text limit while producing text. Preflight ZIP-based DOCX/XLSX archives against a configurable 512 MiB total uncompressed-size cap before parsing; fail clearly rather than expanding unbounded archives.
- Run ingestion in a supervised worker process with a 15-minute per-file parse deadline, cancellation, and progress updates. Embedding progress is separate; do not apply the parse deadline to full-file indexing.
- Return actionable errors naming the exceeded limit, observed size/count, and effective maximum. Reject corrupt, encrypted, or unsupported files. Explain that scanned PDFs need OCR, which is outside v1.
- Use 450-token prose chunks with 60-token overlap; preserve table boundaries. Retrieve eight Chroma candidates, then select relevant sentences/fields locally.
- Larger ingestion limits do not increase cloud prompt budgets. Large documents stay local; no automatic full-document transmission.

## Privacy, routing, and reliability

- Combine regex/checksum detectors, local spaCy NER, generic field-name heuristics, and editable YAML policy. Cover contacts, addresses, DOB, government-ID-like patterns including Aadhaar/PAN, Luhn-validated cards, financial and health fields.
- Detect sensitive information in questions, evidence, and outgoing metadata. Use opaque source IDs; keep filenames local. Never automatically transmit conversation history.
- Withhold unrelated sensitive fields/spans. Tokenize necessary values with request-specific placeholders whose maps remain local.
- Before using necessary sensitive data, request scoped consent describing category, purpose, and proposed representation. Bind consent to question, evidence, document versions, and policy; expire after ten minutes. Raw disclosure needs a separate explicit override.
- Perform supported sums/counts/comparisons/date calculations locally; do not ask a cloud model to calculate over opaque placeholders. Restore only exact known placeholders and validate cited evidence IDs.
- Treat document instructions as untrusted evidence. Abstain when evidence is insufficient; visibly flag citation or placeholder verification failures.
- Cloud base URL: `https://api.withprune.com/v1`. Authenticate with backend-only `X-Prune-Key`; Gemini adapter route `/proxy/gemini/generateContent`. Tag calls with `X-Prune-Feature-Id`.
- Use a narrow HTTP client with no direct-provider fallback. Set `X-Prune-Cache: off` by default; exact cache is a separate synthetic repeat experiment.
- Interactive defaults: approximately 2,048 context tokens, 512 output tokens, 50,000 reserved tokens per session, and one generation per answer. Reserve budgets atomically and count each attempt.
- Cloud timeout: 45 seconds. At most two retries with backoff for safe connection failures or ordinary rate limits. Never automatically retry Shield rejections or ambiguous post-dispatch timeouts. Fail closed on every Shield rejection.
- Persist the exact outgoing serialized body before dispatch, destination, attempt, payload hash, status, usage, and response metadata. Audit-write failure blocks dispatch. Never log credential headers.
- Preserve original `prune_metadata` and verify Ed25519 signatures with Prune's public key and documented canonicalization. Missing/invalid signatures are visibly unverified, never fabricated.
- Receipts distinguish application minimization, Prune optimization/cache savings, and signature verification. A Prune signature authenticates its receipt, not an independent proof of all application behavior.

## API and UI

Typed API endpoints cover effective configuration, uploads, ingestion status/cancellation, files, demo loading, questions, scoped consent, receipts, history search/deletion, evaluation summary, and delete-all. Question results distinguish `consent_required`, `answered`, and `blocked`.

- Single central ask bar, small top-left upload button, top-right privacy button, collapsible searchable local history.
- Bottom answer drawer supports peek, expanded, loading, consent, and error states, with keyboard/click/drag/scroll interaction.
- Privacy panel contains mode switch, exact sent content, withheld categories, local-only reveal, receipt verification, and evaluation summary.
- Local Starry Night reproduction with attribution/public-domain provenance, subtle optional displacement, static fallback, hidden-tab pause, and reduced-motion support. Centralize colors, typography, spacing, and motion; make the background replaceable.
- Report measured frame timing rather than claiming an untested 60 fps. Display effective larger upload limits consistently in the upload UI and errors.
- Mode A badge: “External requests observed by Atlas: 0” only when supported by the application audit. Clearly describe the audit's application scope.

## Evaluation and acceptance

Generate obviously synthetic datasets: a 20-page employee PDF with policy and personal fields, clinic notes, a contract, and customer CSV/XLSX. Include all parser formats as fixtures. Plant canaries and create 36 gold questions, nine per dataset, including sensitive requests, missing evidence, and document prompt injection.

```text
uv run atlas dev
uv run atlas eval --live --synthetic-full-context --resume
```

- Run paired full-synthetic-document and minimized requests through Prune with identical requested models/settings and caching off. Full-context permission is restricted to generated fixtures.
- Inspect exact outbound request bodies for unrelated pipeline canaries. Report baseline exposure separately.
- Use deterministic gold facts, regex, numeric checks, and citations; no LLM judge.
- Report observed provider usage, exact bytes, locally estimated prompt tokens, withheld fields, and paid-list-price equivalents separately. Do not present nominal savings as money actually saved from a free-tier bill.
- Preserve Prune's own optimization/cache fields separately; never add overlapping savings. Run a distinct exact-cache repeat experiment.
- Produce Markdown and JSON with completed/failed/skipped/quota-blocked counts and show the summary in the privacy panel. Resume without repeating completed requests.
- Bound live evaluation to 100 attempts and one million estimated tokens; start serially at four requests/minute. Pause on exhausted quota with an honest incomplete report.
- Test detectors, Luhn, placeholder round trips/collisions, consent invalidation, query PII, injection, budget races, Shield rejection, audit failures, signature tampering, all parsers, deletion, and local-mode networking.
- Chroma tests: persistence across restart, correct local embedder in both directions, no default embedder, invalid-vector rejection, incompatible-index rejection, deleted-file exclusion, and offline indexing/querying.
- Limit tests: exact upload boundary succeeds and one byte above fails; row/page/extracted-byte boundaries; missing or inaccurate Content-Length; ZIP expansion limits; worker timeout/cancellation and partial-file cleanup. Use small overridden limits for routine tests plus a streamed 100 MiB upload check without embedding the filler.
- Targets, not claimed outcomes: zero unrelated pipeline canary leaks, at least 90% deterministic correctness, and no more than five percentage points below baseline. Report failures openly.
